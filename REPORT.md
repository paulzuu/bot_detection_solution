# Выявление автоматизированного сбора данных

Итоговый вариант — CatBoost на поведенческих признаках за сутки. На отложенных 17–19 апреля
получилось **0,6512 по Precision при Recall ≥ 70%**. На скрытом тесте качество не измерялось: его разметки нет.

## Данные и очистка

В train 11 091 cookie, из них 899 ботов — 8,1%. В test 4 909 cookie. Обучение относится к 6–19 апреля,
тест — к 20–26 апреля. Пересечений cookie_id между ними нет.

Самая важная проверка оказалась связана со временем. Из 328 905 событий **40 779 лежат уже после окончания
окна наблюдения**. В эту группу попадают все 7 928 показов капчи. Если посчитать признаки по всему файлу,
модель получит информацию, которой на момент решения ещё не было.

Оставлены события из полуоткрытого интервала `[window_start_ts, window_end_ts)`. Затем удалены 4 293 полных
дубликата внутри окна. После очистки осталось 283 833 события. У каждой cookie есть хотя бы одно событие.
Разные действия с одинаковым временем сохранены, но их неизвестный порядок не используется при расчёте переходов.

Пропуски обрабатываются с учётом смысла поля. Например, отсутствие номера страницы у просмотра объявления
не превращается в страницу 0. Если статистику нельзя рассчитать, она получает значение −1;
нулевые счётчики остаются нулевыми.

## Признаки и модель

Количество событий само по себе оказалось слабым сигналом. Более полезны интервалы между действиями,
разнообразие объявлений и категорий, глубина поиска и сочетания действий с одним объявлением.

Собраны 191 числовой признак. В итоговой модели используются 169: из неё исключены прямые признаки платформы
и User-Agent. Остались счётчики и доли действий, уникальность и энтропия объектов, статистики пауз,
короткие серии активности, сессии, глубина выдачи, повторяемость точек курсора и возраст cookie.
Пауза более 30 минут отделяет сессии. Значения этой границы не подбирались по финальной проверке.

Сырые ID, строки запросов, версии браузеров и абсолютные даты в модель не поступают. Значения item_id нужны
только для подсчёта разнообразия и сопоставления действий внутри cookie. Признаки разных cookie вычисляются
независимо: нет общих частот по train и test или кодирования категорий через target.

Использован локальный CatBoost: 800 итераций, глубина 6, learning rate 0,04, L2-регуляризация 8, seed 42.
В итоговом варианте веса классов одинаковые. Порог к предсказаниям не применяется: в CSV сохраняется score.

## Валидация и эксперименты

Модель выбиралась по двум последовательным временным блокам. Для первого обучение заканчивается 12 апреля,
проверка проходит 13–14 апреля. Для второго обучение заканчивается 14 апреля, проверка — 15–16 апреля.
Последние три дня использованы только после фиксации конфигурации. Ранней остановки по ним нет.

Метрика взята из `metric.py` задания без изменений. Для baseline использован Random Forest на двух признаках
из quickstart: число событий и число уникальных объявлений. Очистка событий у всех моделей одинаковая.

| Вариант | 13–14 апреля | 15–16 апреля | Среднее P@R70 |
|---|---:|---:|---:|
| RF, два счётчика | 0,0837 | 0,1039 | 0,0938 |
| CatBoost без статистик времени | 0,3358 | 0,4889 | 0,4124 |
| HistGradientBoosting | 0,5714 | 0,6875 | 0,6295 |
| CatBoost, исходные признаки с клиентом | 0,6084 | 0,6846 | 0,6465 |
| CatBoost, расширенные признаки без клиента | **0,6042** | **0,6929** | **0,6485** |
| Тот же вариант, среднее трёх запусков | 0,5669 | 0,6742 | 0,6206 |

Также проверены глубины 4 и 7, дополнительные оценки регулярности и вес положительного класса 3.
Все результаты сохранены в ноутбуке и `results/development_results.csv`.
Удаление временных статистик явно ухудшает результат. Разница между двумя лучшими конфигурациями небольшая;
она не доказывает преимущество одной из них. Выбран вариант без прямых признаков клиента, поскольку
его качество сопоставимо и он меньше зависит от окружения. Усреднение не улучшило основную метрику.

## Финальная проверка и ошибки

| Метрика на 17–19 апреля | Baseline | Выбранная модель |
|---|---:|---:|
| Precision при Recall ≥ 70% | 0,0931 | **0,6512** |
| Average Precision | 0,1627 | 0,7396 |
| ROC-AUC | 0,5749 | 0,9165 |
| Recall при FPR ≤ 1% | 0,0688 | 0,5500 |

В точке основной метрики найдено 112 из 160 ботов. Ошибочно отмечено 60 человеческих cookie,
48 ботов пропущено. Порог 0,1676 выбран по меткам этой проверки по правилам задания;
это не гарантия 70% recall на новых днях. В ноутбуке отдельно показан перенос порога с более ранних блоков.

Короткие истории остаются слабым местом: при пяти событиях или меньше найдено 4 из 14 ботов,
при более чем 30 событиях — 37 из 44. Среди важных признаков — разнообразие объявлений и категорий,
средняя короткая пауза, доля интервалов до минуты и возраст cookie.

Стратифицированный bootstrap по cookie даёт широкий 95% интервал P@R70: **[0,438; 0,789]**.
Он отражает шум небольшой проверочной выборки при фиксированной доле классов, но не перенос на новые сервисы
и не неопределённость повторного обучения. По отдельным дням метрика меняется от 0,475 до 0,667.

Разметка описывает известные источники автоматизированного трафика. Отдельного ID источника нет,
поэтому проверку на полностью неизвестном сервисе провести нельзя. Чистота отрицательного класса также
неизвестна. Score используется для ранжирования; его калибровка как вероятности не проверялась.
Следующий полезный шаг — получить больше размеченных дней и идентификатор источника,
а затем проверить перенос на новые семейства ботов.

После проверки та же конфигурация обучена на всём train. Файл `submission.csv` содержит ровно 4 909 строк
в порядке test и ровно две колонки. Код фиксирует seed и версии библиотек; `run.py --verify` заново
создаёт CSV и сравнивает его контрольную сумму. В расчёте используются pandas, NumPy, SciPy,
scikit-learn и CatBoost; графики построены в Matplotlib. LLM и внешние API в пайплайне отсутствуют.
